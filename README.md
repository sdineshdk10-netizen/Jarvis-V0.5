# JARVIS v0.2 — mobile-first development build
Python 3.11+; install requirements in a virtual environment. Copy .env.example to .env and replace JARVIS_TOKEN with output of `python -c 'import secrets; print(secrets.token_urlsafe(32))'`. Never share the token or API key. Run `python -m uvicorn app:app --host 127.0.0.1 --port 8765`. Open http://127.0.0.1:8765 and connect with the token. Install a compatible Ollama build and pull llama3.2:3b for local AI. If Intel Mac compatibility fails, use a compatible llama.cpp server adapter (not included) or cloud mode. For cloud mode configure an OpenAI API key and a supported chat-completions model ID; billing is separate. Cloud selection sends workspace notes and recent chat to provider. No automatic fallback or hard spending cap.
For iPhone access, deploy behind authenticated private HTTPS (e.g. Tailscale Serve on a supported Mac, or private HTTPS cloud deployment); keep server running. Do not expose bare Uvicorn publicly. Open HTTPS address in Safari and Add to Home Screen. The manifest is included; no offline AI or offline caching. No hosted URL is included. Voice and wake-word integration intentionally deferred. No native iOS build. SQLite is unencrypted; single-user token grants all workspaces, not separate accounts. Do not store sensitive office data. Use disk encryption and restrict file permissions. Plugins list is a roadmap; only UTC clock executes. Extend TOOLS with explicitly authorized handlers, never arbitrary shell execution. Memory is manually saved and chat history persists; no automatic extraction. Cloud spending requires provider-side controls; no guaranteed ₹1500 cap. No Mac control yet. Browser and physical iPhone testing required.

## V0.3 additions
Read-only Google adapters: Gmail message IDs (not email contents), Drive file metadata, Calendar events. Supply OAuth credentials and a refresh token obtained through your own Google Cloud OAuth consent flow with gmail.readonly, drive.metadata.readonly, calendar.readonly scopes. No built-in consent flow yet. Never share credentials in chat. Natural language routing supports exact phrases such as `show my emails`, `list my drive files`, `show my calendar`, `current time`. Other requests use the selected AI model. Memory ranking uses keyword overlap, not embeddings. Google live calls, iPhone installation, Canva and custom voice are not tested or implemented as applicable. No automatic cloud spending cap. Existing installation instructions apply.

## V0.4 prototype
Voice settings select Tamil, English or Tanglish. Optional browser speech reads new AI replies; voice availability and mixed-language pronunciation depend on the device. Original actor voice, microphone input, cloud sync and live device tests remain pending. Provider-neutral voice adapter included but not wired to a live provider.

## V0.5 launch candidate
Added optional browser microphone transcription into the editable chat box. Press Send to submit. Tanglish uses Tamil recognition locale as a fallback; mixed language accuracy is not verified. Browser support varies; use keyboard dictation if unavailable. Microphone requires secure context and permission; browser vendor may process audio remotely. No original actor voice or live hosting.
Quick Mac launch: run `bash start.sh` from this directory, then open the displayed localhost URL and enter the generated private token. For AI responses install Ollama and pull the configured model, or configure cloud credentials locally in .env. The clock and memory can be tested without an AI provider.
